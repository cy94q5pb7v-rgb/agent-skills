# presentation

Скилл превращает агента в дизайнера-аналитика презентаций, который собирает **один автономный HTML-файл** со слайдами 1920×1080 — открывается двойным кликом в любом браузере, листается стрелками `← →` / пробелом, печатается в PDF. Движок встроен в файл, внешняя зависимость одна — веб-шрифт (есть системный фолбэк).

Две опоры скилла:
1. **Аналитика, а не пересказ.** Скилл читает исходный материал, вытаскивает факты и числа, **считает производные** (доли, динамику, суммы) — но только из реальных данных — и показывает цифры там, где они сильнее текста.
2. **Аккуратная вёрстка без догадок.** Слайды строятся из готовых сеток, которые не переполняются и **заполняют кадр**, а в конце дека проверяется скриптом-аудитором.

## Что на входе и выходе

- **Вход:** тема + вводные (Фаза 1). Сильно желателен **источник** — документ/текст/таблица/цифры, на которых строится дека.
- **Выход:** **ровно один файл** `<тема>.html` в рабочей папке. Движок встроен — никаких отдельных `.js`, папок, черновиков. Самодостаточный, оффлайн-готовый (кроме веб-шрифта).
- **Язык:** по входным данным; по умолчанию русский. Шрифт обязан поддерживать язык (кириллица — `references/layout-system.md` §7).

## Когда применять / когда нет

Применяй на любую просьбу про презентацию/слайды/deck/питч, открывающиеся в браузере.

**Не применяй**, если нужен редактируемый PowerPoint как главный артефакт, или это интерактивный веб-прототип, а не линейные слайды.

## Принципы (читать до начала)

- **Ничего не выдумывай.** Цифры, факты, цитаты, названия — только из брифа/источника или посчитанные из них. **Нет данных в исходнике — НЕ показывай** (не дописывай «правдоподобные» числа и общие фразы). Лучше убрать блок/слайд, чем выдумать. Пустой, но честный — допустимо; выдуманный — нет.
- **Анализируй и считай.** Не пересказывай текст буллетами. Извлеки числа, посчитай **производные из реальных данных** (доли %, рост/динамику, суммы, средние, «было → стало») и покажи их (роль `stats` / `chart`), если это сильнее текста.
- **Заполняй кадр.** Свободного пространства должно быть мало: контент занимает ~85–95% полезной области, а не «висит» в центре с пустыми полями. Пустует низ/бока → увеличь типографику и блоки, добавь реальный элемент (цифру, мини-график, инсайт) или объедини слайды. Пустота = недоделанность (см. `layout-system.md` §2).
- **Возник вопрос — спроси.** Данные неоднозначны, непонятна структура слайда, не хватает факта для расчёта, не ясна аудитория/акцент → задай вопрос пользователю (`AskUserQuestion`). Не угадывай и не выдумывай в обход вопроса.
- **Один слайд — одна мысль.** Не влезает — дели.
- **Заголовок — это вывод, а не тема** (action title). По одним заголовкам читается вся история (ghost-deck test).
- **Борьба с «ИИ-эстетикой»** обязательна (`references/anti-ai-checklist.md`).
- **Сначала проверь, потом сдавай** (`references/self-check.md`).

## Рабочий процесс

### Фаза 0. Контекст (без вопросов, если данные есть)

Прочитай бриф и **весь приложенный материал** (документ/текст/таблица/цифры). Если упомянут бренд/палитра/референс — учти. Не переспрашивай то, что уже дано.

### Фаза 1. Режим + интервью

**1.0 — Режим работы. Спроси ПЕРВЫМ** (если пользователь сам не указал) через `AskUserQuestion`:
- **Авто** — скилл сам собирает всю деку по материалу и вводным, в конце показывает результат. *(по умолчанию)*
- **Послайдово** — по каждому слайду скилл предлагает 2–3 варианта структуры/наполнения + свою рекомендацию и ждёт выбора, прежде чем верстать.

**1.1 — Вводные.** Сначала проверь бриф на сигналы (аудитория / стиль / длина). Если **≥2 из 3** уже есть — не дублируй их, спроси только недостающее. Полный набор (консолидируй в 1–2 `AskUserQuestion`, не засыпай по одному):
1. **Тема и одна цель** — о чём дека и какое **одно** действие/решение нужно от зрителя.
2. **Аудитория** — кто смотрит, уровень, настрой.
3. **Объём** — слайдов или длительность (≈1–2 мин/слайд).
4. **Нужны ли цифры/метрики?** — да, это ядро / по ситуации, где уместно / нет, только смыслы.
5. **Источник данных для цифр и графиков** — есть в приложенном материале / пришлю отдельно / бери только то, что в тексте / данных нет.
6. **Плотность** — low (под доклад) / high (под чтение). По умолчанию low, но помни про правило «заполняй кадр».
7. **Тон/бренд** — формальный/живой; есть ли бренд-цвета/шрифты (для «Сбер» — пресет из `layout-system.md` §6).
8. **Заметки докладчика** — нужны ли.

**1.2 —** Чего-то не хватает для генерации — **спроси**, не выдумывай дефолт по важным вещам (данные, аудитория, акцент).

### Фаза 1.5. Анализ материала (если источник есть)

Прежде чем верстать:
1. **Разбери источник:** факты, числа, разделы/структуру, ключевые выводы.
2. **Посчитай производные** из реальных данных, где это усиливает мысль: доли (%), динамику/рост, суммы, средние, «было → стало». **Не выдумывай недостающие значения** — если для расчёта не хватает данных, спроси или не считай.
3. **Реши, где цифры сильнее текста** → роль `stats` (крупные числа) или `chart` (CSS-бары, см. `layout-system.md`). Если цифры не нужны / данных нет — строй на смыслах, без чисел.
4. **Составь карту слайдов** (outline): для каждого — роль + что на нём (из реальных данных). Заголовки сразу формулируй как выводы.
5. **Выпиши открытые вопросы** (чего не хватает, что неоднозначно) и **задай их пользователю** до вёрстки.

### Фаза 2. Визуальная система (зафиксируй до вёрстки)

Одним абзацем: палитра (1 фон + 1 акцент + нейтраль, 60/30/10), пары шрифтов (с поддержкой языка!), роли слайдов и где 1–2 инверсных (тёмных) слайда для ритма. Подбери цвет под тему, **не уходи в дефолтный синий/фиолетовый**. Бренд назван (например «в цветах Сбера») → возьми пресет из `references/layout-system.md` §6.

### Фаза 3. Сборка — по выбранному режиму

1. Скопируй `templates/deck.html` как `<тема>.html`. **Создаётся ровно один файл.**
2. Поменяй токены в `:root` под систему/бренд.
3. Верстай по **`references/layout-system.md`** — основной справочник (роли, рамка, бюджет, **заполнение кадра**, авто-усадка, цвет, шрифты, графики).

**Общие правила (оба режима):**
- **Заполняй кадр** — контент на ~85–95% полезной области, без больших пустот.
- Чередуй роли (тезис → колонки → цифры → график → цитата → сравнение), не повторяй подряд.
- Action titles; числа — только реальные/посчитанные; крупный текст — `data-fit`.
- НЕ делай первый слайд пустым «титульником».

**Режим АВТО:** собери всю деку по карте слайдов за один проход → Фаза 4 → покажи результат.

**Режим ПОСЛАЙДОВО:**
1. Покажи **карту слайдов** (общий план) и получи ОК.
2. По каждому слайду (или логичной группе) через `AskUserQuestion` предложи **2–3 варианта** раскладки/наполнения + **свою рекомендацию** (помечай «рекомендую»), всегда с опцией «свой вариант». Свёрстай выбранное.
3. Не утомляй: 1 компактный вопрос на слайд (роль + акцент), а не десять.
4. В конце — общая самопроверка (Фаза 4).

### Фаза 4. Самопроверка (обязательно, блокирует сдачу)

По **`references/self-check.md`**:
1. **Бюджет высоты + заполнение** — каждый слайд: ничего не вылезает И нет больших пустот.
2. **Аудитор:** `node scripts/audit.mjs <тема>.html` — любой `FAIL` → чини и перезапускай; браузера нет (код 3) → опирайся на бюджет/чеклист и честно скажи об этом.
3. **Нарратив** — action titles + ghost-deck test.
4. **Данные** — каждая цифра прослеживается в источнике/расчёте; ничего не выдумано.
5. Есть скриншоты/vision — пройди ручной визуальный чеклист.

### Фаза 5. Открыть и предложить дальнейшее

Открой файл (ниже) или дай путь. Предложи: **PDF** (Ctrl/Cmd+P → «Сохранить как PDF»), **PPTX** по-картинкам (если есть инструмент), заметки докладчика.

## Как открыть .html

- **Windows:** `cmd //c start "" "C:\путь\<тема>.html"`
- **macOS:** `open <тема>.html` · **Linux:** `xdg-open <тема>.html`
- В headless/CI не открывай — сообщи путь.

## Структура скилла

```
presentation/

├── references/

```

## Антипаттерны — жёстко нельзя

- ❌ Выдуманные/«правдоподобные» цифры и факты. Нет в источнике — не показывай.
- ❌ Большие пустоты / «воздух» без причины. Заполняй кадр.
- ❌ Угадывать вместо вопроса, когда данные неоднозначны.
- ❌ Первый слайд — пустой титульник.
- ❌ «Спасибо за внимание» на финале — вместо этого вывод + действие + контакт.
- ❌ Тонкая линия-акцент под заголовком; эмодзи-иконки; фиолетовые градиенты; glassmorphism; дефолтные Inter/Roboto/Arial.
- ❌ Шрифт без поддержки языка (кириллица «квадратами»).
- ❌ Одна раскладка на всех слайдах.
- ❌ Сдать деку без `audit.mjs` (или, если браузера нет, не сказав об этом).
- ❌ Плодить лишние файлы — презентация это **один** `.html`.

## Чеклист перед сдачей

1. Режим согласован; открытые вопросы заданы и закрыты.
2. Каждая цифра прослеживается в источнике/расчёте — ничего не выдумано.
3. `audit.mjs` без `FAIL` (или честно сказано, что браузер недоступен).
4. **Кадр заполнен** — нет больших пустот; контент на ~85–95% площади.
5. Заголовки — выводы; ghost-deck test проходит.
6. Раскладки чередуются; 1–2 инверсных слайда; палитра 60/30/10; шрифт поддерживает язык.
7. Пройден анти-ИИ чеклист; финал = вывод + действие.
8. Файл открыт / путь передан; предложены PDF/PPTX.
