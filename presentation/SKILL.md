# presentation

Скилл превращает агента в дизайнера презентаций, который собирает **один автономный HTML-файл** со слайдами 1920×1080 — открывается двойным кликом в любом браузере, листается стрелками `← →` / пробелом, печатается в PDF. Движок слайдов встроен в файл, внешняя зависимость одна — веб-шрифт (есть системный фолбэк).

Ключевая идея: слайды строятся **не «на глаз», а из готовых фиксированных сеток, которые физически не переполняются**, а в конце дека **проверяется скриптом-аудитором**. Это даёт аккуратный результат даже без браузера-превью и vision-модели под капотом.

## Что на входе и выходе

- **Вход:** тема + вводные (см. Фазу 1). Опционально — текст/документ-источник, бренд, палитра.
- **Выход:** файл `<тема>.html` в рабочей папке. Самодостаточный, оффлайн-готовый (кроме шрифта).
- **Язык:** определяется по входным данным; по умолчанию русский. Шрифт обязан поддерживать язык (для кириллицы — см. `references/layout-system.md` §7).

## Когда применять / когда нет

Применяй на любую просьбу про презентацию/слайды/deck/питч, открывающиеся в браузере.

**Не применяй**, если нужен редактируемый PowerPoint как главный артефакт (тогда экспортируй HTML в PPTX по-картинкам, см. Фазу 5, либо используй отдельный pptx-инструмент), или если это интерактивный веб-прототип, а не линейные слайды.

## Принципы

- **Не выдумывай данные.** Цифры, факты, цитаты — только из брифа/источника. Нет данных — честный плейсхолдер или вопрос пользователю, не фантазия.
- **Один слайд — одна мысль.** Не влезает — дели, а не уплотняй.
- **Заголовок — это вывод, а не тема** (action title). По одним заголовкам должна читаться вся история (ghost-deck test).
- **Борьба с «ИИ-эстетикой»** — обязательна (`references/anti-ai-checklist.md`).
- **Сначала проверь, потом сдавай.** Считай, что дефекты есть, и ищи их (`references/self-check.md`).

## Рабочий процесс

### Фаза 0. Контекст (без вопросов, если данные есть)

Прочитай бриф. Если пользователь приложил документ/текст/таблицу как источник содержания — прочитай и извлеки оттуда структуру и факты. Если упомянут бренд/палитра/референс — учти. Не переспрашивай то, что уже дано.

### Фаза 1. Интервью (собрать вводные)

**Сначала проверь бриф на 3 сигнала:** есть ли **аудитория** («для инвесторов», «для команды»), **стиль** (named: «минимализм», «как Apple», бренд), **длина** («N слайдов», «коротко»).

- Если **≥2 из 3** уже есть → не задавай длинный опросник, уточни максимум 1–2 пробела и начинай.
- Если **<2** → задай вопросы (минимум по делу, не засыпай):
  1. **Тема и цель** — о чём дека и какое **одно** действие/решение нужно от зрителя после неё?
  2. **Аудитория** — кто смотрит, их уровень, настрой.
  3. **Главный вывод** — одна фраза, которую должны унести.
  4. **Количество слайдов** (или длительность выступления → прикинь: ~1–2 минуты на слайд).
  5. **Режим плотности** — под доклад (low, спикер говорит) или под чтение/рассылку (high). По умолчанию low.
  6. **Тон/стиль** — формальный/живой, сдержанный/смелый; есть ли бренд-цвета/шрифты.
  7. **Будут ли заметки докладчика.**

Если что-то не назвали — выбери разумный дефолт и скажи об этом, не блокируйся.

### Фаза 2. Визуальная система (зафиксируй до вёрстки)

Одним абзацем проговори: палитра (1 фон + 1 акцент + нейтраль, правило 60/30/10), пары шрифтов (с поддержкой языка — кириллица!), какие роли слайдов используешь и где будут 1–2 инверсных (тёмных) акцентных слайда для ритма. Подбери цвет под тему, **не уходи в дефолтный синий/фиолетовый по инерции**.

### Фаза 3. Сборка

1. Скопируй `templates/deck.html` в рабочую папку как `<тема>.html`.
2. Поменяй токены в `:root` (цвета/шрифты) под выбранную систему.
3. Замени слайды-примеры на свои. Один слайд = один `<section>` с классом-ролью. Бери готовые блоки и правила бюджета высоты из **`references/layout-system.md`** — это основной справочник вёрстки.
   - **НЕ** делай первый слайд пустым «титульником» — обложка должна нести реальный посыл.
   - Чередуй роли раскладок (тезис → карточки → цифры → цитата → сравнение), не повторяй одну подряд.
   - Крупный текст помечай `data-fit` (авто-усадка длинных слов/чисел).
   - Заголовки — выводы (action titles). Числа — только реальные.
4. Заметки докладчика (если нужны) — `<script id="speaker-notes" type="application/json">[...]</script>` в конце `<body>`, по строке на слайд.

### Фаза 4. Самопроверка (обязательно, блокирует сдачу)

Следуй **`references/self-check.md`**:
1. **Бюджет высоты** (уровень 1) — мысленно сверь каждый слайд.
2. **Аудитор** (уровень 3): `node scripts/audit.mjs <тема>.html`
   - Любой `FAIL` (переполнение / наезжание / плейсхолдер) → **чини и перезапускай**. Не сдавай с FAIL.
   - `WARN` (тесно) → желательно поджать.
   - Браузера нет (код 3) → опирайся на бюджет + ручной чеклист и честно скажи пользователю, что инструментальная проверка не запускалась.
3. **Нарратив** — action titles + ghost-deck test (по одним заголовкам читается вся история).
4. Если доступны скриншоты/vision — пройди ручной визуальный чеклист (наезжание, пустые слайды, контраст, кириллица без «квадратов»).

### Фаза 5. Открыть и предложить дальнейшее

- Открой файл (см. ниже) или дай путь пользователю.
- Предложи: печать в **PDF** (в браузере Ctrl/Cmd+P → «Сохранить как PDF», размер уже настроен на 1920×1080), экспорт в **PPTX** по-картинкам (если в проекте есть инструмент экспорта), режим заметок докладчика.

## Как открыть .html

- **Windows:** `cmd //c start "" "C:\путь\<тема>.html"` — откроется в браузере по умолчанию.
- **macOS:** `open <тема>.html`
- **Linux:** `xdg-open <тема>.html`
- В headless/CI приложение не открывай — просто сообщи путь.

## Структура скилла

```
presentation/

├── templates/
│   └── deck.html                  # болванка: встроенный движок + примеры всех ролей + токены
├── references/
│   ├── layout-system.md           # роли-раскладки, бюджет высоты, data-fit, цвет, шрифты — ОСНОВНОЙ справочник вёрстки
│   ├── anti-ai-checklist.md       # признаки «ИИ-деки» и чем заменять

└── scripts/
    └── audit.mjs                  # headless-аудит: переполнение, наезжание, плейсхолдеры
```

## Антипаттерны — жёстко нельзя

- ❌ Первый слайд — пустой титульник. Сразу к содержанию/посылу.
- ❌ Выдуманные цифры, факты, цитаты.
- ❌ «Спасибо за внимание» на финале — вместо этого вывод + действие + контакт.
- ❌ Тонкая линия-акцент под заголовком (признак ИИ).
- ❌ Эмодзи как иконки, фиолетовые градиенты, glassmorphism-карточки, дефолтные Inter/Roboto/Arial.
- ❌ Шрифт без поддержки языка (кириллица «квадратами»).
- ❌ Одна и та же раскладка на всех слайдах.
- ❌ Сдать деку, не прогнав `audit.mjs` (или, если браузера нет, не сказав об этом честно).

## Чеклист перед сдачей

1. Все обещанные слайды на месте; данные не выдуманы.
2. `audit.mjs` — без `FAIL` (или честно сообщено, что браузер недоступен).
3. Заголовки — выводы; по ним читается вся история (ghost-deck test).
4. Раскладки чередуются; 1–2 инверсных слайда для ритма.
5. Палитра ≤ 3 ролей цвета (60/30/10); шрифт поддерживает язык.
6. Пройден анти-ИИ чеклист; финал = вывод + действие.
7. Файл открыт или путь передан пользователю; предложены PDF/PPTX.
