# presentation

Скилл-дизайнер: из твоего материала собирает **один автономный HTML-файл** со слайдами 1920×1080 (движок встроен, листается `← →` / пробелом, печатается в PDF). По умолчанию — фирменный стиль Сбера (белый/зелёный, Golos Text). Рассчитан на слабую модель: опирается на план-файл (внешняя память) и скрипт-аудитор, а не на «дисциплину в уме».

## ⚡ ЯДРО — 5 пунктов (если удержишь только это, уже выйдет нормально)

1. **Спроси и жди.** Фаза 1: режим + вводные простым текстом → дождись ответа, не начинай без него.
2. **План в файл.** `presentation/<тема>.plan.md`: блоки + **Реестр данных** (числа с источником) + план на **РОВНО N слайдов**, по которым распределена ВСЯ информация.
3. **Числа — только из реестра.** Ничего не выдумывай; нет данных — не показывай.
4. **Каждый слайд — форма из содержания**, формы варьируй; стиль уже Сбер (`:root` не трогай); заполняй кадр.
5. **Прогони `audit.mjs`** (`--selftest`, затем аудит `--plan`): `FAIL` → чини; нет браузера → сверь высоту вручную. Без аудита не сдавай.

## Вход / выход

- **Источник:** сильно желателен документ/текст/таблица/цифры, на которых строится дека.
- **Все файлы → папка `presentation/`** (нет — создай: `mkdir presentation`): результат `presentation/<тема>.html` (самодостаточный) + рабочая память `presentation/<тема>.plan.md`. Больше **ничего не плоди**; в конце предложи удалить план или оставить как бриф.
- **Язык** — как у входа; шрифт обязан поддерживать язык (кириллица — `references/layout-system.md` §7).

## Когда применять / когда нет

Применяй на любую просьбу про презентацию/слайды/deck/питч, открывающиеся в браузере. **Не применяй**, если нужен редактируемый PowerPoint как главный артефакт или интерактивный веб-прототип.

## Правила вкуса (детали — `references/anti-ai-checklist.md`)

- **Современно, стильно, прогрессивно — и максимум пользы.** Целься в уровень топовой дизайн-студии, а не «офисный шаблон PowerPoint»: чистая типографическая иерархия (огромный заголовок против мелкого caption), структурные сетки с линиями-разделителями, фирменный зелёный как акцент, рамка и круг-мотив Сбера, ритм из 1–2 тёмных слайдов. Каждый слайд несёт **максимум ПОЛЕЗНОЙ информации** по своей мысли — плотно, по делу, **без воды и без пустот** (но без перегруза: держись бюджета высоты и читаемости).
- **Форма следует за содержанием.** Для каждого слайда определи форму из того, что он должен сказать (число → цифра/график; сравнение; шаги; перечень → колонки; мысль → тезис; цитата). Готовые формы под каждый тип контента — **галерея `references/forms.md`** (бери `<section>` целиком, наполняй); это словарь, который комбинируешь, а не меню. **Варьируй** формы (соседние слайды — разной структуры). **Первый слайд — обложка** (`layout-cover`) с реальной главной мыслью (не пустой титульник).
- **Заполняй кадр** (~85–95% полезной области), пустота = недоделанность. **Исключение** — тезис/цитата/обложка (`statement`/`quote`/`cover`): им положен воздух.
- **Заголовок = вывод** (action-title), а не тема. По одним заголовкам читается история (ghost-deck test).
- **Без ИИ-слопа.** Только токены `:root` (Сбер бело-зелёный), новые цвета не вводи. Нельзя: линия-акцент под заголовком, эмодзи-иконки, фиолетовые градиенты, glassmorphism, Inter/Roboto/Arial. Финал — вывод + действие, не «Спасибо за внимание».

## Рабочий процесс

### Фаза 0. Контекст
Прочитай бриф и **весь приложенный материал**. Бренд/палитру/референс — учти. Уже данное не переспрашивай.

### Фаза 1. Вопросы — ОБЯЗАТЕЛЬНЫЙ первый шаг (стоп-ворота ⛔)
Задай вопросы и **дождись ответа** — твой ход на этом заканчивается, к Фазе 2 не переходи. Способ: есть инструмент выбора (`AskUserQuestion`/`ask`) — используй; нет — **простым нумерованным списком в чат**. Исключение одно: пользователь сам написал «сделай сам / не спрашивай» (а «и так всё понятно» — НЕ повод пропустить).

- **1.0 Режим:** *Авто* (соберу сам) или *Послайдово* (по каждому слайду 2–3 варианта + рекомендация).
- **1.1 Вводные** (спроси недостающее, консолидируй): 1) тема и одна цель (одно действие от зрителя); 2) **тип деки** — питч / отчёт-аналитика / статус / обучение / обзор (предложи вероятный, дай подтвердить — задаёт нить); 3) аудитория; 4) объём (слайдов/длительность); 5) нужны ли цифры; 6) источник данных; 7) плотность low/high; 8) бренд (по умолчанию Сбер); 9) заметки докладчика.
- **1.2** Не хватает чего-то по ходу — снова спроси (данные/аудитория/акцент не выдумывай).

### Фаза 2. Анализ и архитектура → в `presentation/<тема>.plan.md`
Не верстай, пока нет плана. Шаблон файла — `references/pipeline.md`. Большой источник анализируй субагентом (если CLI умеет).

1. Создай папку `presentation/` и в ней `<тема>.plan.md`.
2. **Блоки** — раздроби материал на атомарные факты/идеи/числа/выводы.
3. **Реестр данных** (`Показатель | Значение | Источник | Слайд`) — только реальные и посчитанные из реального значения; нет данных — не вноси. Слайды берут числа ТОЛЬКО отсюда.
4. **План слайдов** на **РОВНО N** (число задано → строго оно; нет → под объём). Распредели по ним **ВСЮ** информацию — уплотняй/объединяй/приоритизируй, **не плоди лишние и не обрезай**; не лезет даже после уплотнения → спроси. Для каждого слайда: сообщение (action-title) · что показать по сути · ссылки на реестр · приоритет (P0/P1/P2) · шаг нити (по типу деки, `pipeline.md` §1 — не навязывай pitch-структуру отчёту). Прогони ghost-deck test.
5. **Дизайн-система:** по умолчанию Сбер (уже в шаблоне) — не меняй. Другой бренд только если назван явно: тогда поменяй и токены `:root`, и слово «Сбер» в рамке `.fr`, и точку-логотип `.wm .dot`. Реши, где 1–2 инверсных слайда для ритма.
6. **Открытые вопросы** — задай пользователю до вёрстки.

### Фаза 3. Сборка по плану — форма каждого слайда ИЗ содержания
Собирай по одному слайду, **каждый раз сверяясь с планом** (не по памяти). В шаблоне — **стартовый набор из 6 разных форм** (образцы): подбери форму под каждый слайд, замени плейсхолдеры на реальный контент, **сохрани разнообразие** (не делай все одной формой), лишние удали, нужные подбери из **галереи `references/forms.md`** (раздел под «что показать» из плана). Первый слайд — обложка.

**Путь выбирается АВТОМАТИЧЕСКИ** (не решай сам): **есть субагенты → ПРЕДПОЧТИТЕЛЬНО** отдавай сборку КАЖДОГО слайда отдельному субагенту — со своим самодостаточным **СЛАЙД-БРИФОМ** (данные + форма из `forms.md` + стиль + контекст соседей; шаблон брифа — `pipeline.md` §2.2). У каждого слайда чистый контекст → выше качество; затем критик-арт-директор (`anti-ai-checklist.md`) на P0-слайды + QA через `audit.mjs`. Нет субагентов → собирай сам, последовательно, перечитывая план. Полное «агентство» и усилители — по явной просьбе (`pipeline.md` §5).

1. Скопируй `templates/deck.html` → `presentation/<тема>.html`. `:root` не трогай (Сбер), кроме явно названного бренда.
2. Форму каждого слайда подбери под «что показать» из плана → возьми готовый `<section>` из **галереи `references/forms.md`** (там формы сгруппированы по типу контента, 1–4 варианта на каждый), скопируй целиком и наполни. Адаптируй/комбинируй. Числа — строго из реестра.
3. Дисциплина: заполняй кадр, бюджет высоты (~590px под контент), `data-fit` на крупном тексте, **варьируй формы**, ровно N слайдов со всей информацией.

**Авто:** собери всё → Фаза 4 → покажи. **Послайдово:** сначала покажи «План слайдов» и получи ОК; затем по каждому слайду предложи 2–3 формы (из содержания) + рекомендацию, свёрстай выбранное, отметь готовым; в конце — Фаза 4.

### Фаза 4. Самопроверка (блокирует сдачу) — `references/self-check.md`
1. **Бюджет высоты** — мысленно: ничего не вылезает, нет больших пустот (кроме airy-форм).
2. **Аудитор:** `node scripts/audit.mjs --selftest`, затем `node scripts/audit.mjs presentation/<тема>.html --plan presentation/<тема>.plan.md`. Проверяет переполнение/наезжание/недозаполнение, наличие `.fr`/`.pg`, повтор форм, плейсхолдеры, **сверку чисел с реестром**. `FAIL` → чини и перезапускай. **«⚠️ ГЕОМЕТРИЯ НЕ ПРОВЕРЕНА»** (нет браузера) → сверь высоту вручную и честно скажи пользователю.
3. **Нарратив** — ghost-deck test (по заголовкам читается история).
4. **Данные** — каждая цифра в деке есть в реестре; нет — убери или найди источник.

### Фаза 5. Открыть и предложить дальнейшее
Открой файл или дай путь. Предложи: PDF (`Ctrl/Cmd+P` → «Сохранить как PDF»), PPTX по-картинкам (если есть инструмент), заметки докладчика. Спроси про `<тема>.plan.md`: удалить или оставить как бриф.

**Открыть:** Windows `cmd //c start "" "<путь>"` · macOS `open <путь>` · Linux `xdg-open <путь>`. В headless — просто дай путь.

## Структура скилла

```
presentation/
├── SKILL.md                  # этот файл — ядро + процесс
├── templates/deck.html       # шаблон: движок + рамка + CSS-словарь форм + токены Сбера + СТАРТОВЫЙ набор из 6 разных форм
├── references/
│   ├── forms.md              # ГАЛЕРЕЯ форм по типу контента: готовые <section> для копирования (бери под «что показать»)
│   ├── pipeline.md           # план-файл (схема), субагенты, агентство ролей, фолбэк
│   ├── layout-system.md      # рамка, бюджет/заполнение, цвет (пресет Сбер), шрифты, правила вёрстки
│   ├── anti-ai-checklist.md  # признаки «ИИ-деки» и чем заменять
│   └── self-check.md         # уровни проверки + нарратив + чеклист
└── scripts/audit.mjs         # аудит: геометрия (переполнение/наезжание/недозаполнение), .fr/.pg, повтор форм, плейсхолдеры, сверка чисел; фолбэк без браузера
```

## Антипаттерны — жёстко нельзя

- ❌ Начать делать деку, не задав вопросы (кроме явного «сделай сам»).
- ❌ Верстать до плана; держать анализ «в голове» вместо `plan.md`.
- ❌ Однотипные слайды (все одной формой) / оставить плейсхолдер-текст из стартового набора. Подбери форму под содержание, замени контент, варьируй.
- ❌ Выдуманные цифры и факты; число не из реестра.
- ❌ Раскидать инфу на больше слайдов, чем просили, и обрезать лишнее. Держи N, вмещай уплотнением — или спрашивай.
- ❌ Большие пустоты без причины (кроме airy-форм).
- ❌ Новые/чужие цвета и ИИ-слоп (линия под заголовком, эмодзи, градиенты, Inter); шрифт без кириллицы; «Спасибо за внимание».
- ❌ Сдать деку без `audit.mjs` (или, если браузера нет, не сказав об этом).
- ❌ Плодить файлы сверх двух (`.html` результат + `.plan.md` память).

## Чеклист перед сдачей

1. Вопросы заданы и закрыты; есть `plan.md` (блоки + реестр + план на N).
2. Каждая цифра — из реестра; ничего не выдумано.
3. `audit.mjs` без `FAIL` (или честно сказано про отсутствие браузера).
4. Кадр заполнен; формы чередуются; первый слайд — по содержанию.
5. Заголовки-выводы, ghost-deck проходит; пройден анти-ИИ чеклист.
6. Файл открыт / путь передан; предложены PDF/PPTX.
