# Самопроверка деки

Главное требование скилла: **дека не сдаётся, пока не проверена**. Ничего не должно наезжать, ничего не должно быть обрезано, и заголовки должны рассказывать историю. Проверка идёт в три уровня (от дешёвого к точному) плюс текстовые проверки нарратива.

> Принцип Anthropic: **«Считай, что проблемы есть. Твоя задача — их найти»**. Не «выглядит ок», а активный поиск дефектов.

---

## Уровень 1 — арифметика бюджета (всегда, без инструментов)

Ещё до генерации каждого слайда прикинь высоту контента против бюджета **≈ 660px** (см. `layout-system.md` §2). Если не влезает — **разбей слайд или сократи**, не пихай. Это ловит ~80% переполнений до того, как они появятся.

## Уровень 2 — непротекаемая сетка by-construction

Используй готовые роли-раскладки из `layout-system.md`. Они заполняют область 888px и не переполняются при разумном объёме контента. Крупный текст помечай `data-fit` — движок сам ужмёт длинное слово/число. Это не отменяет уровень 1: `data-fit` — страховка, а не право на лишний контент.

## Уровень 3 — инструментальный аудит `scripts/audit.mjs`

Точная проверка геометрии в headless-браузере. Запусти из папки скилла:

```bash
node scripts/audit.mjs <путь-к-деке.html>
```

Что мерит по каждому слайду:
- **переполнение** по вертикали и горизонтали (контент за пределами 1920×1080);
- **наезжание** — попарное пересечение текстовых блоков;
- **плейсхолдеры** — протёкший мусор-заглушка (`lorem`, `placeholder`, «Option A», `TODO`, текст из шаблона).

Как читать вывод:
- `✗ FAIL` — дефект. **НЕ сдавать.** Чини (см. рычаги ниже) и **перезапусти аудит**.
- `! WARN` — тесно (запас снизу < 40px, для кириллицы < 60px). Желательно поджать.
- `✓ OK` — чисто.

Коды выхода: `0` чисто · `1` есть FAIL · `2` ошибка вызова · `3` браузер недоступен.

**Если код 3 (браузера нет):** аудит не выполнен — обопрись на уровни 1–2 и ручной чеклист ниже, и честно скажи пользователю, что инструментальная проверка не запускалась. Поставить движок:
```bash
npm i -D puppeteer            # со своим Chromium
# или
npm i -D playwright && npx playwright install chromium
```
На Windows можно указать системный Chrome: переменная `PUPPETEER_EXECUTABLE_PATH` → путь к `chrome.exe` (тогда хватит `npm i -D puppeteer-core`).

**Важно:** аудит всегда читает файл заново с диска. Если правил HTML — просто перезапусти, кэша нет. Расхождение «глаза видят переполнение, скрипт молчит» обычно значит, что смотришь старую версию в браузере: обнови вкладку.

### Рычаги починки FAIL
- переполнение по высоте → меньше `min-height` карточек, заголовок на шаг мельче, убрать строку, поджать `gap`, слить кикер с заголовком, **разбить слайд**;
- переполнение по ширине → добавить `data-fit`, сократить слово/число, уменьшить колонок;
- наезжание → проверить абсолютное позиционирование; если слои намеренные — пометить `data-allow-overlap`;
- плейсхолдер → дописать реальный контент (или удалить пустой слайд).

## Текстовые проверки нарратива (дёшево, мощно)

Геометрия гарантирует, что *ничего не обрезано*, но не гарантирует, что *что-то сказано*. Идеально свёрстанная дека из заголовков-тем всё равно читается как ИИ-вода. Поэтому:

### Action titles (заголовки-выводы)
Каждый заголовок — **законченная мысль-вывод**, а не тема. Сравни:
- ❌ «Результаты пилота» → ✓ «Пилот сократил обработку заявки с 4 часов до 30 минут»
- ❌ «О рынке» → ✓ «Рынок растёт на 24% в год, но 3 игрока держат 70%»

### Ghost-deck test (тест по одним заголовкам)
Выпиши **только заголовки** всех слайдов подряд. Прочитай. Они должны **сами по себе рассказывать всю историю** — завязка → проблема → решение → доказательство → вывод. Если по заголовкам нить теряется — нарратив сломан, чини структуру, а не вёрстку.

### Прочее по содержанию
- **Одна мысль на слайд.** Можешь сформулировать посыл слайда одним предложением? Нет — дели.
- **Никаких выдуманных цифр.** Только то, что дал пользователь или источник.
- **Финал** = вывод + действие + контакт. Не «Спасибо за внимание».

## Ручной визуальный чеклист (если есть скриншоты / vision)

`audit.mjs` ловит геометрию, но не видит контраст, «ИИ-эстетику» и пустые слайды. Если среда позволяет посмотреть на слайды глазами (скриншот, vision-субагент) — пройди:

**Наезжание и коллизии**
- [ ] Текст не пересекает фигуры/линии/декор.
- [ ] Подписи/футеры/номера не наезжают на контент выше.
- [ ] Заголовок в 2 строки не наползает на блок под ним.
- [ ] Нет элементов, торчащих за край слайда (видно при screen-share).

**Пустые / молчаливо-сломанные слайды**
- [ ] Нет слайдов с 1–2 элементами (недозаполненный плейсхолдер).
- [ ] Нет больших пустых цветных прямоугольников (не загрузилась картинка).
- [ ] Заголовок/подзаголовок не пустые.

**Структурные анти-паттерны**
- [ ] Нет тонкой линии-акцента под заголовком (признак ИИ).
- [ ] Не протекли служебные метки («Блок 1 · 10 мин», «Шаг 0 ·», имя шаблона).
- [ ] Раскладки чередуются, а не все одинаковые.
- [ ] Заголовки — выводы, а не «Понимание/Обзор/Про X».

**Кириллица и шрифты**
- [ ] Русский текст рендерится буквами, а не «квадратами» (□□□) — значит, шрифт имеет кириллицу.
- [ ] Код (если есть) — моноширинный, на подложке, с отступами, без переноса строк.
- [ ] Весь текст читается на своём фоне (контраст).

Полный список признаков «ИИ-деки» — в `anti-ai-checklist.md`.
