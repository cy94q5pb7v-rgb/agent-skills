# Мастер-промт презентации

Собирается в Фазе 2 из брифа. Это контекст-якорь, который передаётся каждому субагенту в цепочке (раздел «Контекст» в их промпте).

Сохраняется как `.p-demo/master-prompt.md`.

---

## Шаблон

```
ПРЕЗЕНТАЦИЯ — МАСТЕР-БРИФ

Тип: <pitch / sales / launch / report / education / manifesto / conference>
Цель: <одна цель>
Целевое действие: <что зритель делает после>

Аудитория:
<2–3 строки: кто эти люди, что знают, что им важно>

Формат:
<живое выступление N минут / email / self-paced / печать>
Самодостаточность: <да/нет — нужны ли тексты на слайдах для понимания без рассказчика>

Главный takeaway:
«<одна фраза>»

Контент-сырьё:
<что предоставлено пользователем, что генерируется с пометкой [VERIFY]>

Дизайн-система:
<сценарий A/B/C из брифа + выжимка>
- Палитра: <HEX>
- Шрифты: <имена + URL>
- Тон: <описание>

Tone of voice:
<серьёзный / иронический / технический / ...>

Запреты:
<темы, формулировки, цвета, конкуренты, клише>

Формат вывода:
- HTML: presentation.html (один автономный файл со scroll-snap)
- PPTX: <режим structural / pixel-perfect / нет>
- Размер слайда: <16:9 / 4:3 / другой>

Дедлайн: <дата/время>
Приоритет: <скорость / качество>
```

---

## Что должно быть в финальном мастер-промте

1. **Минимально необходимая информация** для каждого субагента, чтобы он мог принимать решения, не читая весь бриф.
2. **Никаких дублирований и лишнего** — это короткий рабочий документ, не отчёт.
3. **Точные значения вместо описаний** там, где они есть: HEX вместо «тёмный фон», конкретные шрифты вместо «современная типографика».
4. **Запреты явные** — что точно нельзя делать.

После сборки покажи пользователю **компактный вид** на 5–10 строк (не весь промт целиком) и спроси: «Иду запускать lead-дизайнера, всё ок?»
