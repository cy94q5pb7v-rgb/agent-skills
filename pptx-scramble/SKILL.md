# pptx-scramble

Обратимое обезличивание текста в `.pptx`. Меняет **только видимые буквы и
цифры**, побайтово сохраняя всё остальное (разметку OOXML, шрифты, цвета,
позиции, числовые данные графиков). Длина каждой надписи остаётся прежней →
вёрстка и переносы строк не плывут. Оригинал восстанавливается из файла-карты —
**по содержимому**, поэтому работает, даже если слова в промежутке переставили
или перенесли на другие слайды.

## Быстрый старт (это всё, что нужно для запуска)

Скрипт детерминирован — твоя единственная задача подставить путь к файлу.

> **Имена вроде «Демо дека» и дата `2026-06-10_143000` во всех примерах ниже —
> просто иллюстрация. НЕ копируй их.** Бери реальный путь, который дал
> пользователь, и реальные имена файлов из того, что напечатал скрипт.

**Обезличить** (заменить `<ПУТЬ…>` на настоящий путь к презентации):

```bash
python "C:/Users/Никита/.claude/skills/pptx-scramble/scripts/pptx_scramble.py" scramble "<ПУТЬ_К_ИСХОДНОМУ_ФАЙЛУ.pptx>" --into "C:/Users/Никита/Desktop/PPTX-обезличка"
```

**Восстановить** (имена `…-scrambled.pptx` и `…-scrambled.map.json` скрипт
напечатал при обезличивании; запускай из их папки):

```bash
python "C:/Users/Никита/.claude/skills/pptx-scramble/scripts/pptx_scramble.py" restore "<ИМЯ>-scrambled.pptx" "<ИМЯ>-scrambled.map.json"
```

Признак успеха — строка `self-check (length + round-trip): OK` (у `scramble`) или
`Restored … words` (у `restore`). Всё, что ниже, — пояснения и крайние случаи;
для запуска они не нужны.

## Зачем это нужно

Бывает нужно отдать презентацию «в работу», не раскрывая её содержимое: дать
другой (например, слабой) модели или официальному скиллу `pptx` переработать
**дизайн и компоновку** конфиденциальной деки, выложить пример вёрстки, прислать
макет на ревью оформления, обучать на «рыбе». Простое удаление текста ломает
раскладку. Здесь каждый символ заменяется на символ **той же длины и того же
класса**, поэтому слайд выглядит точно так же — но прочитать его нельзя.

## Рабочий цикл (главный сценарий)

1. **Обезличить** оригинал → болванка `*-scrambled.pptx` + карта `*.map.json`.
2. **Переработать болванку** как угодно: другой моделью или скиллом `pptx`
   поменять оформление, порядок слайдов, передвинуть и переставить блоки текста.
   Реальный смысл текста при этом не виден — видна только «рыба».
3. **Восстановить** → реальные слова возвращаются на свои (возможно, новые) места.

Почему шаг 3 переживает перекомпоновку: каждое **слово** заменяется
СОГЛАСОВАННО (одно и то же слово → всегда одна и та же «абракадабра») и
УНИКАЛЬНО (разные слова → разные замены). Поэтому каждая «абракадабра» — это
устойчивый «штрих-код» слова. `restore` ищет эти штрих-коды по всему файлу и
ставит на их место оригиналы, где бы они ни оказались. Позиция не важна.

## Когда применять, а когда нет

- **Этот скилл** — когда задача про *скрыть/обезличить/заменить текст с
  сохранением вида и возможностью вернуть*. Ключевые сигналы: «той же длины»,
  «оставить дизайн», «болванка», «с расшифровкой / для обратной конвертации».
- **Официальный скилл `pptx`** — когда надо *создать, прочитать, осмысленно
  отредактировать или отрендерить* презентацию. Не дублируй его здесь.

Эти два скилла дружат: после обезличивания болванку можно открыть/отрендерить
официальным `pptx` для визуальной проверки, что вид совпал с оригиналом.

## Организация файлов (одна папка на всё)

По умолчанию складывай **каждую обработку в свою подпапку** внутри одной общей
рабочей папки — за это отвечает флаг `--into <корень>`. Скрипт сам создаёт
`<корень>/<имя деки>-<дата_время>/` и кладёт туда **все материалы** прогона:

```
<корень>/                              ← одна папка на всё
└── Демо дека-2026-06-10_143000/       ← одна подпапка на каждую обработку
    ├── Демо дека.pptx                 ← копия оригинала
    ├── Демо дека-scrambled.pptx       ← болванка (отдавать в работу)
    ├── Демо дека-scrambled.map.json   ← карта-«расшифровка» (СЕКРЕТ!)
    ├── README.txt                     ← что есть что + команда restore
    └── Демо дека-restored.pptx        ← появится после restore
```

*(«Демо дека» и дата — пример; реальные имена скрипт берёт от исходного файла.)*

**Стандартный корень на этой машине:** `C:/Users/Никита/Desktop/PPTX-обезличка`
(скрипт создаст его сам, если нет). Используй именно его, пока пользователь не
попросит другой.

## Как пользоваться (главное)

Вся логика — в одном самодостаточном скрипте на чистом Python (стандартная
библиотека, **без** python-pptx, без интернета). Просто запусти его.

**Шаг 1. Обезличить** — всегда с `--into`, чтобы прогон лёг в свою подпапку:

```bash
python "C:/Users/Никита/.claude/skills/pptx-scramble/scripts/pptx_scramble.py" scramble "<путь к.pptx>" --into "C:/Users/Никита/Desktop/PPTX-обезличка"
```

Скрипт выведет сводку и строку `self-check (length + round-trip): OK` — это
встроенная проверка, что длины совпали и восстановление сработает. Если её нет
или есть `Error:` — не выдавай результат за готовый, разберись с ошибкой. В выводе
есть строка `run folder -> ...` — это и есть папка прогона.

**Шаг 2. Сообщи пользователю про папку прогона и три файла в ней** (см. ниже).

**Шаг 3. Восстановить оригинал** (только когда об этом просят) — запускай **из
папки прогона**, поэтому имена файлов короткие, а результат ляжет туда же:

```bash
cd "<папка прогона>"
python "C:/Users/Никита/.claude/skills/pptx-scramble/scripts/pptx_scramble.py" restore "<имя>-scrambled.pptx" "<имя>-scrambled.map.json"
```

## Что получается на выходе

В папке прогона (`<корень>/<имя>-<дата_время>/`) лежат:

1. **`<имя>.pptx`** — копия исходника (чтобы всё по задаче было в одном месте).
2. **`<имя>-scrambled.pptx`** — презентация с обезличенным текстом. Это то, что
   можно безопасно отдать наружу.
3. **`<имя>-scrambled.map.json`** — «расшифровка»: карта, по которой `restore`
   точно вернёт оригинал.
4. **`README.txt`** — короткая памятка, что есть что и как восстановить.
5. **`<имя>-restored.pptx`** — появится после шага 3.

> ⚠️ **Карта `.map.json` хранит ОРИГИНАЛЬНЫЙ текст в открытом виде.** Это и есть
> секрет. Её нельзя отправлять вместе с болванкой — иначе обезличивание теряет
> смысл. Предупреди об этом пользователя. Без карты восстановить нельзя.

(Без `--into` скрипт работает по-старому — кладёт болванку и карту рядом с
исходным файлом. Это запасной режим для разовых задач.)

## Что именно делает замена

- буква → случайная буква того же регистра и алфавита (кириллица↔кириллица,
  латиница↔латиница);
- цифра → случайная цифра (реальные числа, в т.ч. финансовые, скрываются);
- пробелы, знаки препинания, символы, эмодзи — **остаются на месте** (это держит
  границы слов и переносы строк, поэтому раскладка не меняется);
- длина каждой надписи **идентична** исходной — символ в символ;
- замена **согласованная и уникальная**: одно и то же слово всюду получает одну и
  ту же «абракадабру», разные слова — гарантированно разные. Именно это позволяет
  `restore` находить и возвращать слова по содержимому, даже после перекомпоновки.

Пример: `EXECUTIVE DEMO` → `DPYOPUMZG DPAM`; `01 / 03` → `29 / 14`.

## Опции `scramble`

- `--into <корень>` — **рекомендуется**: положить прогон в свежую подпапку
  `<корень>/<имя>-<дата_время>/` вместе с копией оригинала и README. Держит все
  материалы одной задачи вместе; перекрывает `--out`/`--map`.
- `--out <файл.pptx>` — куда сохранить болванку (по умолчанию `<имя>-scrambled.pptx`).
- `--map <файл.json>` — куда сохранить карту (по умолчанию рядом с болванкой).
- `--seed <N>` — зерно генератора (по умолчанию `1`); один и тот же seed даёт
  воспроизводимый результат. На обратимость не влияет (restore работает по карте).
- `--all-text` — обезличивать ещё и шаблонные слои (slideLayouts/slideMasters).
  По умолчанию они не трогаются: там обычно нет реального контента, только
  каркас. Включай, если в мастере зашит конфиденциальный текст.
- `--no-verify` — пропустить встроенную самопроверку (не рекомендуется).

## Что НЕ затрагивается (честные ограничения)

- **Картинки, фото, логотипы, встроенные объекты** — остаются как есть. Если на
  слайде секрет нарисован картинкой, замените/удалите её отдельно (скиллом `pptx`).
- **Числовые данные графиков** (числовой кэш `<c:v>`) намеренно сохраняются,
  чтобы диаграммы не сломались; обезличиваются только текстовые подписи графика.
  Если сами цифры графика секретны — это надо делать вручную через `pptx`.
- **Слои-шаблоны** по умолчанию не трогаются (см. `--all-text`).
- **Текст, дописанный на шаге переработки** (которого не было в оригинале), не
  восстанавливается — его нет в карте. `restore` возвращает только слова из
  исходника; всё новое остаётся как есть (в выводе — счётчик «left as-is»).
- **Разорванное слово.** Если редактор расколет одну «абракадабру» на части
  между двумя текстовыми фрагментами, такой обломок может не сопоставиться. Целые
  перемещённые слова сопоставляются всегда.

## Проверка качества

Скрипт проверяет себя сам (длины + round-trip в памяти) перед записью. Поэтому
отдельный прогон ради «убедиться, что длина та же» не нужен — достаточно увидеть
`OK` в выводе. Для визуального контроля вида открой болванку официальным `pptx`
(рендер в картинки) и сравни с оригиналом — раскладка должна совпадать.
